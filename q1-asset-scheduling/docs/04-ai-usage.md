# 04 AI 使用说明

本题从拆解到实现都大量使用了 AI 编码助手。这里如实写明哪些是 AI 做的、我本人做了什么，以及怎么验证 AI 的产出。

## 使用的工具

- **AI 编码 Agent：Claude Code**。前期规划阶段和实现阶段各有一个会话，都在我给出的约束下工作；
- **被测模型：阿里云百炼 qwen3.8-max**。它是 Agent 运行时调用的模型，不参与写代码。

## AI 完成的部分

| 阶段 | AI 做了什么 | 我做了什么 |
|---|---|---|
| 前期规划（`PLAN.md`） | 拆解四道题、对比选题、设计共用骨架、整理交接文档 | 决定只做 Q1；选定模型和接入方式（百炼 OpenAI 兼容接口）；提供 API Key；定下“commit 不带 AI 署名”“不用自有服务器做核心验收”等约束；确定演示域名和部署方式 |

## 怎么验证 AI 的产出

1. **可执行的测试**：`python -m pytest -v`，结果见 `examples/test-results.txt`。测试按“这条断言能不能真的失败”来写，例如脚本化 Mock 故意谎报保存成功，断言校验器把状态改成 `failed`。
2. **真实模型的证据只来自实跑**：`examples/*.trace.json` 都是 `scripts/record_examples.py --llm real` 的原始输出，没有手工改过；`tests/test_examples.py` 断言每份录制满足用例里的 `expected`，提示词版本和工具定义指纹都与当前代码一致（改了就必须重录），并把录制里模型发出的每个工具调用在当前代码上原样重放、逐步比对返回结果。
3. **稳定性**：`scripts/eval_stability.py --runs 3` 对每个用例重复实跑，结果见 `examples/stability-report.json` 和 `docs/03` 第 4 节。
4. **独立复核**：实现完成后，另起一个只读的复核会话，专门检查“越权发布 / 虚报保存成功 / 防重复”三类问题，结论见 `docs/03` 第 6 节。
5. **密钥检查**：提交前检查仓库里没有 API Key 和私有工作空间地址；`.env` 已被 `.gitignore` 排除，只提交 `.env.example`。
